## 问题

传统 Dense 模型主要通过增加参数量来提升模型容量，但在 MoE 中，可以通过增加 Expert 数量来扩大模型的总参数量，同时保持每个 Token 激活的 Expert 数量不变，从而在不显著增加计算量的情况下提高模型容量。

这引出了一个问题：MoE 的稀疏度应该如何选择？增加 Expert 数量是否始终有利于模型能力的提升？

特别是对于记忆型任务和推理型任务，两者可能具有不同的需求：

1. **记忆能力（Memorization）：** 更大的总参数量意味着更大的模型存储容量，可以容纳更多知识和模式。但在固定训练数据量下，增加 Expert 也会使每个参数能够获得的训练数据相对减少。
2. **推理能力（Reasoning）：** 除了模型总容量，还依赖每个 Token 实际激活的计算量，以及参数是否得到充分训练。因此，单纯增加 Expert 数量可能导致推理性能下降。

因此，需要研究总参数量、激活参数量和训练数据量之间的关系，确定不同任务下 MoE 的最优稀疏度。

## 总结

系统研究了 MoE 稀疏度对记忆型任务和推理型任务的影响，发现两类任务具有不同的 Scaling 特征：

- **记忆型任务：** 更倾向于增加总参数量、提高稀疏度。在固定激活计算预算下，增加未激活的 Expert 能够扩大模型的有效存储容量，从而改善知识记忆与提取能力。
- **推理型任务：** 需要同时考虑每个 Token 的激活计算量和训练数据量。激活计算量不足或者每个参数获得的训练数据不足，都可能损害推理能力。

作者进一步提出两个决定 MoE 最优稀疏度的关键因素：

1. Active FLOPs：每个 Token 实际激活的计算量。即使预训练 Loss 相同，激活计算量更大的模型也可能具有更好的推理能力。
2. Total Tokens Per Parameter（TPP）：总训练 Token 数与模型总参数量之比。记忆型任务倾向于较低 TPP，而推理型任务在本文实验中约为 20 TPP 时表现较好。

此外，GRPO 和增加 Test-Time Compute 虽然能够提高推理性能，但无法消除预训练阶段由稀疏度引起的性能差异。

## 思路

作者首先采用 Mixtral 风格的 MoE 架构，固定训练数据量为 125B Tokens，通过改变模型宽度、Expert 总数和 Top-k，构建不同总参数量、激活参数量和稀疏度的模型。

随后围绕记忆能力与推理能力之间的差异展开实验。

**1. 研究总参数量对不同任务的影响**

固定模型宽度和 Top-k，只增加每层 Expert 总数 E。

此时总参数量增加，但每个 Token 激活的 Expert 数量不变。

实验发现：
- TriviaQA、HellaSwag 的预训练 Loss 和下游 Task Loss 均持续下降。
- GSM8K、GSM-Plus 的预训练 Loss 持续下降，但下游 Task Loss 会先下降后上升。

说明增加 Expert 数量能够持续改善模型的预训练拟合能力和记忆型任务表现，但推理型任务存在最优 Expert 数量，超过之后继续增加参数反而会损害推理性能。

**2. 研究固定计算预算下的最优稀疏度**

通过控制激活参数量，改变 Expert 总数和 Top-k，比较不同 MoE Density 下的任务表现。

其中：

\[
\text{Sparsity}=1-\frac{k}{E}
\]

实验发现：
- 记忆型任务：在相同激活参数量下，稀疏度越高，表现通常越好。
- 推理型任务：计算预算较小时，提高稀疏度有利；随着激活参数量增加，最优配置逐渐转向更稠密的模型。

这说明记忆型任务更依赖模型整体容量，而推理型任务还需要足够的实际激活计算量。

**3. 研究训练数据量与总参数量的关系**

引入 TPP 指标：

\[
TPP=\frac{\text{Total Training Tokens}}{\text{Total Parameters}}
\]

通过改变总参数量，观察不同任务在不同 TPP 下的表现。

实验发现：
- 记忆型任务：TPP 越低，通常表现越好，即更大的模型参数容量有利于知识存储。
- 推理型任务：呈现非单调趋势，在本文实验中约 20 TPP 时表现较好。

作者认为，增加 Expert 数量虽然能够扩大模型的有效存储容量，但在固定数据量下，也会使更多参数得不到充分训练。记忆型任务能够从额外容量中受益，而推理型任务则更容易受到训练数据不足的影响。

**4. 验证后训练与推理阶段计算能否弥补预训练差异**

分别采用两种方法：
- Test-Time Compute：使用 Self-Consistency，每道 GSM8K 题目生成 27 个独立答案，通过多数投票确定最终答案。
- Post-training：使用 GRPO 在 GSM8K 训练集上进行强化学习微调。

实验发现，两种方法都能提高整体性能，但无法消除不同稀疏度模型之间原有的推理性能差异。

**5. 验证结论是否适用于代码生成**

使用 Stack-Edu Python 和 DCLM-dedup Web Text 构建 125B Tokens 的训练语料，在 HumanEval 和 MBPP 上进行评估。

结果同样发现：计算预算较小时，高稀疏度更有利；随着激活参数量增加，最优配置逐渐向更稠密的模型转移。

## 使用方法和技巧

### MoE Sparsity：衡量专家稀疏度

使用 Expert 总数 E 和每个 Token 激活的 Expert 数量 k 计算稀疏度：

\[
S=1-\frac{k}{E}
\]

S 越高，说明模型中未被每个 Token 激活的 Expert 比例越高。

### Active FLOPs：衡量实际激活计算量

关注每个 Token 实际参与计算的 Expert 数量，而不是只看模型总参数量。

在相同预训练 Loss 下，较大的 Top-k 能够为推理任务提供更多激活计算量，从而获得更好的推理表现。

### Total Tokens Per Parameter：衡量数据与模型容量的关系

\[
TPP=\frac{D}{N}
\]

其中 D 为训练 Token 总数，N 为模型总参数量。

- 低 TPP：参数相对较多，训练数据相对不足，倾向于有利于记忆型任务。
- 高 TPP：参数相对较少，训练数据相对充足。
- 对推理型任务，需要在模型容量和训练数据量之间寻找平衡。

### Iso-FLOP Comparison：固定激活计算预算比较稀疏度

在相同激活参数量下，改变 E 和 k，比较不同 MoE Density 的任务表现。

这种方法可以将总参数容量与实际激活计算量区分开来，避免仅通过模型总参数量判断 MoE 的性能。

### Memorization vs. Reasoning：区分不同任务的 Scaling 特征

使用 TriviaQA、HellaSwag 代表记忆型任务，使用 GSM8K、GSM-Plus 代表数学推理任务，并分别观察 Task Loss 和 Accuracy。

核心技巧是：不要直接将预训练 Loss 的下降等同于下游能力的提升，而要分别研究不同能力的 Scaling 趋势。

### GRPO / Self-Consistency：验证后训练与推理阶段的补偿能力

使用 GRPO 和 Self-Consistency 分别增加训练阶段和推理阶段的计算投入，检验预训练阶段形成的稀疏度差异能否被后续方法弥补。
